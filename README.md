# Campus Museum

공부하다 잠시 쉬어 가고 싶을 때 방문하기 좋은 캠퍼스 핫스팟을 소개하는 웹 프로젝트입니다. 카페 멘사, 인커라, 다솔관의 특징과 찾아가는 방법, 추천 활동을 한눈에 확인할 수 있습니다.

사이트: https://tqwuis.github.io/campus-museum/

### 실습 2

#### 데이터 출처 URL / 내려받은 날짜

[KOSIS 국가통계포털](https://kosis.kr/)에서 데이터를 내려받았으며, 2026년 9월 21일을 기준으로 확인했습니다.

#### 데이터 선택 이유 / 대상·기간·단위

건강한 상태를 유지하는 방법에 관심이 있어 건강 상태와 건강관리 습관 데이터를 선택했습니다.

- 건강 상태 데이터: 2021년, 15세 이상 대상
- 건강관리 유형 데이터: 2024년, 13세 이상 대상
- 그래프 단위: 건강 상태 점수, 건강관리 실천율(%)

#### 그래프 1: 사용한 열 / 그래프 형식과 선택 이유 / 해석

CSV의 4번째 열을 사용하고, 수치의 연령별 변화를 나타내기 위해 선 그래프를 선택했습니다.

연령대가 높아질수록 건강 상태 점수가 낮아지는 경향이 있으며, 특히 청년층(10\~30대)과 노년층(60세 이상)에서 점수 차이가 눈에 띄게 나타납니다. 이를 통해 두 연령층에서 자신의 건강 상태 변화를 크게 체감할 가능성을 생각해 볼 수 있습니다.

#### 그래프 2: 사용한 열 / 그래프 형식과 선택 이유 / 해석

5, 7, 9번째 열을 사용하고, 건강관리 유형별 실천율을 비교하기 위해 막대 그래프를 선택했습니다.

20\~39세는 아침 식사 실천율이 낮고, 40대는 규칙적 운동 실천율이 가장 낮아 연령별 취약 관리 방법이 다르게 나타납니다. 적정 수면 실천율은 13\~19세를 제외한 전 연령대에서 비교적 안정적입니다.

#### 필터링·집계·결측치 처리

두 CSV에서 각각 `연령` 또는 `연령별`인 행만 필터링했습니다.

건강 상태 데이터에서는 4번째 열을 사용하고, 건강관리 유형 데이터에서는 `아침 식사`, `적정 수면`, `규칙적 운동` 열만 사용했습니다.

#### 두 탭 전환 방식

버튼을 클릭하면 버튼의 `data-panel` 값과 같은 `id`를 가진 `section`만 `hidden` 속성을 `false`로 바꾸어 표시합니다.

#### 휴대전화에서 두 탭을 확인한 결과

두 탭 모두 화면이 잘리는 부분 없이 정상적으로 표시되었습니다.

#### 빈 데이터·잘못된 CSV를 넣었을 때 결과

그래프가 표시되지 않으며, CSV 경로나 네트워크를 확인하라는 상태 메시지가 표시됩니다.

#### Copilot 활용

CSV 데이터를 그래프로 옮기는 작업에 활용했습니다.

대표 질문:

> CSV 파일을 읽고 적합한 그래프 형태가 어떤 것인지 추론하고 현재 그래프에서 부족한 것을 어떻게 보완할 수 있는지 생각해서 알려줘. 수정사항은 그래프 형태만 바꿔야 해.

필터링되는 열은 직접 수정하고 검증했습니다.

### 실습 3

#### 게임 이름 / 아이디어 / 조작과 규칙

게임 이름은 **BLACK HOLE SURVIVAL**입니다.

블랙홀 주변에서 운석을 피하며 우주선이 오래 생존하는 게임입니다. 드래그로 우주선을 이동하고, 운석이나 블랙홀에 부딪히면 게임이 종료됩니다.

#### Copilot에게 보낸 첫 질문

```text
HTML, CSS, JavaScript를 사용해서 웹페이지 안에서 실행할 수 있는 간단한 미니게임을 만들어줘.

게임의 컨셉은 **블랙홀을 피해 오래 살아남는 우주선 생존 게임**이다.
```

#### 추가 수정 요청과 개선한 점

블랙홀의 중력이 실제 이동에 영향을 주도록 속도 기반 이동으로 수정했습니다. 또한 운석 난이도, 충돌 범위, 모바일 입력 처리를 보완했습니다.

#### 직접 확인한 동작: 조작 / 점수 / 종료 / 재시작

드래그로 우주선이 정상적으로 이동하고 생존 시간에 따라 점수가 증가하는 것을 확인했습니다.

운석이나 블랙홀과 충돌하면 게임이 종료되며, `RETRY` 버튼으로 정상적으로 재시작됩니다.

#### 휴대전화에서 확인한 결과

터치 드래그로 우주선을 조작할 수 있었고, 화면 크기에 맞게 게임 화면이 조정되어 휴대전화에서도 정상적으로 플레이할 수 있었습니다.

### 결과 이름·설명과 선택의 연결

| 결과 유형 | 선택의 의미 | 추천 행동 |
| --- | --- | --- |
| ☕ 단골석 지킴이 (`regular`) | 안정 선택이 더 많아 익숙한 맛과 공간에서 편안함을 찾는 유형 | 좋아하는 자리와 메뉴를 친구에게 소개하며 나만의 단골 코스 함께 즐기기 |
| 🍪 취향 블렌더 (`blender`) | 안정과 도전 선택이 같아 익숙한 즐거움과 새로운 경험을 함께 즐기는 유형 | 단골 카페에서 새로운 디저트를 곁들여 작은 변화 더하기 |
| 🧭 카페 탐험가 (`explorer`) | 도전 선택이 더 많아 처음 만나는 공간과 맛에 호기심을 느끼는 유형 | 아직 안 가 본 학교 근처 카페의 대표 메뉴를 맛보고 친구와 한 줄 감상 나누기 |

- 나만의 표현 한 가지와 구현한 위치: 결과별 해석과 추천 행동을 `CAFE_PROFILES`의 `description`, `recommendation`에 작성했습니다. `showResult()`가 결과 카드의 `#result-description`, `#result-recommendation`에 표시합니다. 추천 행동은 ‘다음 카페에서는 이렇게’ 영역에 강조하고, 크림색 배경과 커피색 포인트로 카페 분위기를 표현했습니다.
- 결과 분류 규칙과 동점 처리: `classifyCafeProfile()`에서 A를 0점, B를 1점으로 더합니다. 도전 선택 횟수인 `adventureCount`가 0\~2점이면 단골석 지킴이, 3점이면 취향 블렌더, 4\~6점이면 카페 탐험가입니다. 안정과 도전이 3개씩이면 중간형으로 처리합니다. 친구 비교는 결과 유형이나 점수 차이가 아니라, 같은 문항에서 같은 선택을 한 개수로 계산합니다.

### 저장 설계

| 저장소 | 키 | 저장한 값 | 선택한 이유 |
| --- | --- | --- | --- |
| `sessionStorage` | `week5.balance.draft` | 참여 ID, 질문 버전, 별명, 질문별 답변, 현재 문항 인덱스(`questionIndex`) | 작성 중인 답변을 같은 탭에서 새로고침한 뒤 이어가되, 다른 탭의 참여와 구분하기 위해 사용했습니다. |
| `localStorage` | `week5.balance.history` | 참여 ID, 질문 버전, 별명, 질문별 답변, 결과 유형, 완료 시각을 담은 기록 배열 | 페이지를 다시 열거나 같은 브라우저의 새 탭에서 접속해도 완료 기록을 조회·비교하기 위해 사용했습니다. 최근 20개를 유지합니다. |

객체와 배열은 `JSON.stringify()`로 문자열로 바꿔 저장하고, 읽을 때 `JSON.parse()`로 복원합니다. 답변은 `{ 질문ID: 선택번호 }` 형태이며 선택번호는 0 또는 1입니다. 별명은 선택 입력이고, 비우면 ‘참가자 1’ 같은 이름을 사용합니다.

저장 키는 기존 `week5.balance.*`를 유지하고 상수 이름은 `CAFE_DRAFT_KEY`, `CAFE_HISTORY_KEY`로 정리했습니다. 질문의 의미가 바뀌었으므로 `CAFE_QUIZ_VERSION`을 `campus-cafe-v1`으로 갱신했습니다. 다른 버전의 임시 답변은 초기화하고, 완료 기록은 표시·비교에서 제외합니다.

- 내 데이터 조회: ‘내 저장 데이터 보기’를 누른 시점의 저장소를 다시 읽어 진행 중 답변과 완료 기록을 표시합니다.
- 임시 답변 삭제: 현재 탭의 임시 답변 키와 메모리의 `activeDraft`를 지우고 시작 화면으로 돌아갑니다. 완료 기록은 유지합니다. 완료하거나 ‘다음 친구 도전’을 눌렀을 때도 임시 답변을 정리합니다.
- 개별 삭제: `deleteRecord()`에서 해당 참여 ID의 기록을 배열에서 제외한 뒤 다시 저장하고, 목록과 결과·비교 화면을 갱신합니다.
- 전체 삭제: 이 게임의 두 저장 키만 `removeItem()`으로 지웁니다. 메모리의 `activeDraft`, `cafeRecords`와 목록·개수·이어하기·결과·비교 화면도 초기화합니다. 다른 실습 데이터를 지우는 `clear()`는 사용하지 않습니다. 다른 탭의 임시 답변은 해당 탭에서 별도로 삭제해야 합니다.

### 확인 결과

직접 실행해 확인한 내용은 **답안 작성 중 새로고침 후 이어하기**와 **새 탭에서 저장된 결과 비교하기**입니다. 새로고침해도 작성 중인 답변을 이어갈 수 있었고, 새 탭에서도 완료 기록을 열어 비교할 수 있었습니다.

추가 검증은 Codex가 Windows의 Chrome 153.0.8010.54를 Playwright로 제어해 수행했습니다. 로컬 HTTP 서버에서 별도 브라우저 컨텍스트를 사용했으며, 화면 폭 390px과 1280px을 확인했습니다. 모바일 크기는 브라우저에서 재현한 것으로 실제 휴대전화 검증은 아닙니다.

브라우저 저장값은 사용자가 개발자 도구로 직접 수정하거나 삭제할 수 있으므로 신뢰할 수 없습니다. 형식이 올바른 데이터라도 실제 사용자가 선택한 답변이라는 사실까지 보장하지는 못합니다.

적용한 방어 방법은 다음과 같습니다.

- JSON 변환과 저장소 접근을 `try...catch`로 처리해 실패 시 기본값 또는 메모리로 진행합니다.
- 읽어 온 데이터의 자료형, 질문 버전, 질문 ID, 답변 범위, 필수 답변, 현재 문항 범위, 별명 길이, 완료 시각과 결과 유형을 검사합니다.
- 저장된 결과 유형이 답변으로 다시 계산한 결과와 일치하는지 확인합니다.
- 참여 ID로 같은 참여의 중복 저장을 방지합니다.
- 별명 등 화면에 넣는 문자열은 `textContent`로 표시합니다.
- 삭제 시 저장소와 메모리·화면을 함께 갱신하고, 이 게임의 키만 삭제합니다.
